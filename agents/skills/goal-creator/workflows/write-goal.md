# 流程：写 /goal 指令

> 把用户当前想自驱的目标，写成一条可发出去的 /goal 指令。

## 阶段 1：理解目标

**目标**：从上下文确认用户要自驱什么
**动作**：
1. 读最近对话，确认用户意图
2. 读项目状态（git log / STATUS / DEV-PLAN）
3. 不清楚 → 问一句确认
**完成**：目标主体明确

## 阶段 2：填模板

**目标**：按 Goal 模板逐项填实
**动作**：
1. 完成条件：写到 evaluator 可自证（"跑什么命令、查什么产出物"）
2. 验证方式：每条完成条件配一个验证手段
3. 约束：只写真约束（别碰某模块、不可逆操作警告）
4. 执行策略：默认用模板那行（一行），特殊打法才展开
5. 填不出的占位行删掉，套话删掉
6. 整条压进 4000 字符
**完成**：模板填实 + 字数合规

## 阶段 3：交付

**目标**：把 /goal 指令给用户
**动作**：
1. 整段放进代码块
2. 附一句"复制这段发送即可启动 /goal"
3. 不可逆操作（commit / push / 部署 / 删除）提醒用户发送前再扫一眼
**完成**：用户可直接复制

## 失败处理

- 阶段 1 不清楚目标 → 问一句，不瞎猜
- 阶段 2 写不出可自证的完成条件 → 回用户确认
- 阶段 2 字数超 4000 → 删套话，保留完成条件
- 阶段 3 用户要修改 → 按反馈重写

## Goal 模板（参考）

```
/goal 完成 <目标>。

完成的标准：
1. <可验证终态>
2. <可验证终态>

验证方式：
- <跑什么命令、查什么产出物>

约束：
- <别碰什么、什么不可逆操作>

执行策略：目标导向，一条路不通换方法，多种都试过才停；长任务记一句进度日志。
```

简单目标只留目标加完成条件两行。
