# 原则：Goal 写作纪律

> /goal 的核心是完成任务。完成条件写到可自证，约束写到精准，每个字带信息。

## 目标必达

- /goal 的核心是完成任务
- 执行策略写成目标导向：一条路不通就换方法，穷尽多种尝试都解不开才停，不一卡就停
- 长任务记一句进度日志

## 完成条件可自证

- 完成标准和验证方式写成 evaluator 能判的形式（/goal 的 evaluator 只判已 surfaced 的内容）
- 跑命令贴输出、列产出物、逐项打勾
- 模糊的"看起来对了""差不多了"等于没写

## 字数硬限

- /goal 有 **4000 字符上限**，超了发不出去
- 写到精准，每个字带信息
- 删套话、删多余格式排版
- 完成条件之外的段，不带信息就不写

## 边界要硬

- 有真实约束才写：别碰某模块、不直推 main 等
- 禁止写"保持兼容性""不要破坏现有功能"这种放之四海的空话
- 不可逆操作（commit / push / 部署 / 删除）必须明确标注

## 不填形式

- 完成条件是唯一必填的核心（evaluator 全靠它）
- 约束、验证、执行策略只在真带信息时写
- 简单目标只留目标 + 完成条件两行

## 联网优先

- 涉及不确定的命令或接口先确认再写进模板
