# 原则：上下文感知

> 从当前环节、用户刚说的、项目状态里推断目标，不让用户从零写。

## 为什么

- /goal 的输入是上下文，不是用户再写一遍的指令
- 用户说"把 v0.3.1 收尾做了"，上下文里有 SPEC/PLAN/git 状态，你直接拼出 /goal 指令

## 怎么做

1. 读最近对话理解用户意图
2. 读项目当前阶段（git log / STATUS.md / dev-planner 进度）
3. 读相关产物（Product-Spec / DEV-PLAN / Design-Brief）
4. 推断目标主体 + 完成条件
5. 不清楚就问一句，不瞎猜

## 反模式

- ❌ 让用户再写一遍刚刚说过的目标
- ❌ 写"请实现..."等空泛开头（不带上下文）
- ❌ 推断不出完成条件就强行写"看起来对了"作完成标志
