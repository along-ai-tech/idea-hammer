# 原则：一句话入口（主线第一段）

> 产品主轴：一句话需求 → 引导补齐 → 可直接交给下游 AI coding 的 Spec。
> 入口不是旁路分支，而是所有 0-1 项目的主线起点：先拆清"这句话包含什么、还缺什么"，再按缺口补齐。

[触发条件]

    - 0-1 模式一律从本段进入，不管用户给一句话还是一段话
    - 用户只给一句话（没同时给角色 / 场景 / 指标 / 范围）→ 本段输出会更长，缺口更多
    - 用户描述较完整 → 仍走一遍，只是盘点结果多为"有"，随后快速进五问
    - 迭代模式跳过本段，直接走 workflow-iteration

[Step 1 · 拆句 → 候选能力]

    按「动词 + 对象」切分原句，每个组合记一条 CAP-###（临时编号，收敛后转 SCOPE / REQ）。
        - 一个动词多个对象 → 拆多条（"查订单、课程、物流" = 3 条）
        - 同一句里的"并且/还/同时"是并列能力信号
        - 主语、渠道、用户身份不在这步猜，留给 Step 2 标缺失

    每条 CAP 标注动作类型：
        只读查询 / 写操作（资金、状态变更）/ 开放问答 / 通知触达

    输出：| CAP | 原句片段 | 动作类型 |

[Step 2 · PRD 维度盘点]

    对照 PRD 七要素，逐项标：有 / 模糊 / 缺失，并写清依据来自原句哪部分。

    | 维度 | 状态 | 依据 / 缺什么 |
    |---|---|---|
    | 背景与目标 | | |
    | 用户角色与画像 | | |
    | 核心问题 | | |
    | 功能范围 | | |
    | 核心业务流程 | | |
    | 产品优先级 | | |
    | 业务指标 | | |

    盘点结果直接决定 Phase 0 五问只问哪几项，已说过的维度不重复问。

[Step 3 · 技术与风控未知项]

    对每条 CAP 至少问三件事：数据从哪来 / 谁会受影响 / 做错了怎么兜底。

    | CAP | 数据与依赖未知 | 权限 / 资金 / 隐私风险 | 失败兜底 |
    |---|---|---|---|

    硬规则：
        - 写操作（退款、改地址、发券、取消订单）默认标"高风险"，v0 默认降级为「查询 + 转人工 / 提交申请」，除非用户明确要求自动执行
        - 需要"查别人的数据"的能力，必须确认身份绑定方式，否则视为越权风险
        - 开放问答必须问知识来源与幻觉兜底，无来源的标缺失

[Step 4 · 收敛到范围与指标]

    按三档给建议（是建议，不是结论）：
        P0：用户高频 + 数据可得 + 失败可兜底 + 只读或低风险
        P1：价值明确但依赖未就绪，或写操作需审批链
        OUT：v0 明确不做，写理由

    指标从"这个能力替掉了人工的哪一步"反推，每条 P0 至少给 1 个：
        自助解决率 / 转人工率 / 首次响应时长 / 处理时长 / 差错率 / 满意度

[Step 5 · 假设与开放问题]

    未知项二分，不允许把"猜"直接写成需求：
        - 可推断 → ASM-### 进 Spec §10.1，写依据 + 猜错的后果
        - 不能推断 → Q-### 进 Spec §10.2，标阻塞 / 非阻塞
        - 一次最多抛 3 个阻塞问题；其余进待确认，不打断主线

[输出]

    一份 PRD 草稿骨架（不是最终 PRD）：
        1. 候选能力表（CAP + 动作类型）
        2. PRD 七要素盘点（有 / 模糊 / 缺失）
        3. 技术与风控未知表
        4. 建议范围（P0 / P1 / OUT）+ 指标候选
        5. 假设表 + 开放问题表（≤ 3 个阻塞）

    然后交给 product-definition，分两轮：先 Discovery 五问（值不值得投入），再用户层 5 问（场景与补齐）；只补盘点里"缺失 / 模糊"的维度。

[与主线的衔接]

    入口 → Discovery → 五问 → Spec 连续完成，中间不产出一份"半成品 PRD"就算交付：
        - 入口负责"拆清 + 找缺口"
        - Discovery 负责"值不值得做"（不展开具体场景）
        - 五问负责"按缺口补齐用户与场景"
        - Spec 成稿负责"组织成下游可执行"
    前两轮不混问：Discovery 没结论，不进入用户场景追问。
    三者共用同一份文档：入口的候选能力进 §2 / §5，盘点结果决定五问问什么，五问答案回填 §1–§4。

[质量判据]

    - 拆句无遗漏：原句每个动词-对象都出现在 CAP 表
    - 每个 P0 都有数据来源与失败兜底
    - 每个未知项都有归属（ASM 或 Q），没有悬空
    - 用户看完能直接回答："先做哪几个、先不做哪个"
