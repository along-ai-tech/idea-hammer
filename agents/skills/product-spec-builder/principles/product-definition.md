# 原则：Phase 0 两轮提问

> 产品主轴：一句话进来 → 先判断值不值得投入（Discovery）→ 再补齐用户与场景（引导补齐）→ 产出可直接交给下游 AI coding 的 Spec。
> 入口（idea-intake）已经把一句话拆成候选能力和缺口清单；两轮提问按缺口补齐，不重复问。

[分轮规则]

    第一轮 · Discovery（商业视角前置层）：只问"值不值得做"，不展开具体用户场景。
    第二轮 · 引导补齐（用户视角）：只问"谁在什么场景被什么卡住、第一版做什么"。
    两轮不能混在同一轮里问：Discovery 没结论，不进入用户场景追问；场景没补齐，不回填 Discovery。
    每轮答案当场落进对应 Spec 字段。

## 第一轮 · Discovery 五问（前置层）

[边界]

    问的是：这件事值不值得投入、有没有更省的做法。
    不问的是：市场规模（TAM/SAM）、变现预测、定价策略、竞品市场份额。
    用户主动提供市场数据可以记录，但不作为门禁；没有数据也不阻塞。
    与产品类型无关：业务参照型和市场机会型都走这五问。

[D1 · 为什么做]

    [主问]
        "为什么要做这件事？背后的业务问题是什么？"
    [追问]
        "现在这个问题造成了什么具体损失（时间 / 钱 / 风险 / 客户流失）？"
    [落点]
        Spec §1.1 产品背景与目标（业务问题 + 损失）
    [合格]
        一句业务问题 + 一个具体损失；不是"想试试 AI"这类技术驱动
    [不合格]
        趋势 / 风口 / 别人都在做

[D2 · 为谁做]

    [主问]
        "哪些用户真正需要？先圈人群，不用讲具体场景。"
    [追问]
        "这些人现在是怎么忍着的？有没有人其实不需要？"
    [落点]
        Spec §1.2 用户角色与画像（角色 + 人群范围）
    [合格]
        1–2 类具体人群，能说出谁不需要
    [不合格]
        所有人 / 开发者 / 中小企业（无边界）
    [与第二轮的界]
        这里只圈"谁"，具体"在哪一步被卡住"留给 Q1，不重复问

[D3 · 价值是什么]

    [主问]
        "做成之后，是增加收入、降低成本，还是降低风险？"
    [追问]
        "哪一项为主？量级大概多少（时间 / 人力 / 金额 / 出错概率）？"
    [落点]
        Spec §1.4 核心价值（价值类型 + 量级）
    [合格]
        明确主价值类型 + 一个量级估计（哪怕是粗略估算）
    [不合格]
        更高效 / 体验更好 / 提升竞争力（无法归因到三类价值）

[D4 · 为什么现在做]

    [主问]
        "为什么是现在？和其他待办需求比，它更紧迫、更重要吗？"
    [追问]
        "如果排到三个月后，会错过什么或多付出什么？"
    [落点]
        Spec §4 产品优先级（紧迫性理由 + 与其他需求的对比）
    [合格]
        一个时间窗口或依赖事件（如业务上线、合规期限、成本拐点）
    [不合格]
        越早越好 / 没有原因，就是想做

[D5 · 值得投入吗]

    [主问]
        "投入产出合理吗？有没有更便宜的替代方案？"
    [追问]
        "最省的替代做法是什么（买现成的 / 人工顶住 / 只做一半）？为什么不用它？"
    [落点]
        Spec §1.1（投入量级与替代方案比较）；不做市场规模与变现预测
    [合格]
        投入量级（人天 / 成本档位）+ ≥ 1 个替代方案 + 不选它的理由
    [不合格]
        没想过 / 肯定值（无估算无对比）

[Discovery 出口]

    三条同时成立才进入第二轮：
        1. 业务问题真实存在（D1 有具体损失）
        2. 价值可归因（D3 能归到增收 / 降本 / 降风险之一）
        3. 投入合理（D5 有替代方案比较，且当前方案不是明显更差的选择）
    任一不成立 → 明确告诉用户"现在不值得做"，记录理由后停止或转向，不硬写 Spec。
    D2 / D4 不达标不阻塞，但必须写进 §10.2 待确认或 §10.1 假设。

## 第二轮 · 引导补齐 5 问（用户视角）

[定位]

    入口产出的是"缺什么"，这一轮负责补齐"用户与场景"。
    每问只问缺口，用户在 Discovery 或原句里已说清的维度不重复问。
    Q1–Q3 必须用苏格拉底式追问法（socratic-questioning.md）：
        澄清 → 检验证据 → 找反例 → 推后果，一次只问一层，下一问基于上一答。

[Q1 · 场景与卡点]

    [主问]
        "最近一次，谁在什么场景下被这件事卡住了？具体到人和场景。"
    [追问]
        "他卡在哪一步？当时怎么处理的？"
        "如果一直不解决，半年后会怎样？"（不做的代价，不单列成问）
    [落点]
        Spec §1.1（不做的代价）+ §1.2（角色 / 场景）+ §1.3（卡点）
    [合格]
        一类具体角色 + 一个有时间地点的实例 + 卡住的那一步 + 不做的代价
    [不合格]
        开发者都需要博客 / 大家都觉得不方便

[Q2 · 现有凑合做法]

    [主问]
        "他今天怎么凑合解决？用了什么工具、土办法，还是干脆忍着？"
    [追问]
        "这个办法最难受的地方是什么？为此付出了什么代价（时间 / 出错 / 放弃）？"
    [落点]
        Spec §1.3 现状与代价；同时成为 §1.7 行业标杆参考里替代方案的行条目
    [合格]
        ≥ 1 个具体现有做法 + 可量化的代价或具体损失
    [不合格]
        没有替代方案 / 就用 Excel 吧（却说不清难在哪）

[Q3 · 解决后的价值]

    [主问]
        "这件事解决后，他哪一处具体变好了？"
    [追问]
        "哪一步可以不用做了？哪件事从做不成变成做成？"
    [落点]
        Spec §1.4 核心价值（与 D3 的价值类型对齐）
    [合格]
        一句 Before → After，能对上 Q1 的卡点和 Q2 的代价
    [不合格]
        更高效 / 体验更好 / 省心

[Q4 · 第一版范围]

    [主问]
        "第一版只做什么？明确不做什么？"
    [追问]
        "这些里哪个是没它就白做的？其余为什么可以往后放？"
    [落点]
        Spec §2.1 / §2.2 / §4
    [合格]
        ≥ 1 条 P0 范围 + ≥ 1 条显式非目标 + 排序理由
    [不合格]
        先都做做看 / 看情况
    [允许]
        非目标可以先标 [待定]，但必须占位

[Q5 · 怎么算做成]

    [主问]
        "上线后，怎么判断它做成了？"
    [追问]
        "能数出来吗？数什么、多少算达标？"
    [落点]
        Spec §1.6 业务指标
    [合格]
        可计数或可观察的达标信号，能回溯到 D3 的价值类型
    [不合格]
        用户说好用 / 感觉不错

[失败处理]

    - 任一问答不上来 → 记进 §10.1 假设（可推断）或 §10.2 待确认（不可推断），不替用户编答案
    - 用户说"先做出来再看" → 记为显式选择写进 §10.2，后续不再反复追问
    - 一次最多抛 3 个阻塞问题，其余进待确认，不打断主线

[出口]

    两轮都完成后进入 Spec 成稿与出口判据检查：下游能否直接据此排任务、写代码。
