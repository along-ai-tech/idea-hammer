# 原则：业务上下文快筛（Phase 0）

> 防方向错最高 ROI 的工具。Spec 写得再漂亮，问题不值得做 = 白干。

[定位]
    这是 Phase 0（Phase 1"问题与人"**之前**）的卡门。轻量 5 问，10 分钟过完。
    不替用户做商业判断，只逼他面对 5 个他多半回避的问题。
    和 scope-discipline 的"不问商业化"不冲突——我们只问"值不值得"，不问"怎么变现"。

[触发条件]
    - 0-1 模式（全新产品）必须走
    - 迭代模式（小功能/UI 调整）跳过，标 [Phase 0 跳过 - 迭代模式]

[5 问快筛]

    [Q1. 用户已经为它付出过什么]
        [覆盖意图]
            验证问题真痛——人为真问题付过时间/钱/工具的钱才叫痛，没付过 = 可能伪需求。
        [主问题]
            "为解决这问题，你的目标用户今天已经付出过什么？时间、钱、工具、还是只在脑子里烦？"
        [接受标准]
            至少 1 项具体的过去付出（买过的工具 / 拼过的土办法 / 浪费的小时数）
        [不接受的答案]
            "他们肯定会付费" / "他们有这个需求"——没行为只有意愿 = 不算数

    [Q2. 凭什么是你]
        [覆盖意图]
            防御"为什么是你而不是大厂/已有玩家"。没差异化 = 做不过。
        [主问题]
            "市面上一定有人想过这事。你比他/她硬100倍的地方是什么？行业经验、数据、技术、已有用户、还是关系？"
        [接受标准]
            至少 1 个具体可指认的差异化（"我有 10000 条历史交易数据" / "我之前在 X 公司做 3 年"）
        [不接受的答案]
            "我会做得更好" / "我比别人更努力"——不可验证 = 没差异化

    [Q3. 1 年后最可能死在哪]
        [覆盖意图]
            强制 pre-mortem：让用户主动想象失败，暴露未察觉的风险。
        [主问题]
            "假设这产品 12 个月后彻底失败了、用户流失到零。最可能死在哪个原因上？给我 3 个，按你觉得的概率排。"
        [接受标准]
            3 个失败原因 + 每个有"我现在能提前发现/防范的信号"
        [不接受的答案]
            "不会失败" / "想不到"——说想不到 = 没真想过 = 没真要做

    [Q4. 怎么变现 / 自用定位]
        [覆盖意图]
            把"商业模式"轻量化——只问定位不问细节。
        [主问题]
            "这产品打算怎么赚钱？付费/广告/数据/引流/或纯粹自用？写一行定位就行，不用细节。"
        [接受标准]
            一行定位（哪怕是"自用"也合理）
        [不接受的答案]
            "以后再想" / "看情况"——没定位 = 后续所有优先级决策都会摇摆

    [Q5. 大厂下场怎么做 你怎么活]
        [覆盖意图]
            护城河自检。防守"巨头一下场你就死"的认知偏差。
        [主问题]
            "如果明天阿里/腾讯/字节/Google 这级别对手也做你这事，你活下来的理由是什么？没有也行——但写下来。"
        [接受标准]
            1 条具体的护城河 / 或显式写"无护城河，靠先发速度"
        [不接受的答案]
            "他们不会做"——巨头做不做和你的护城河无关，巨头不做你也可能被 10 人小团队干掉

[失败处理]
    - 任一题回答不了 → 把"为什么答不了"列出来进 Spec 的 10.1 假设表 / 10.2 待确认表
    - Q3 三个失败原因 → 抽 1 个进 Spec 的 7.2 非功能需求作为要监控的风险信号

[输出]
    不进 Spec 模板（避免膨胀）。但主 Agent 在 Spec 写完后必须显式复盘 5 问是否过完，
    没过完的标 [Phase 0 未过 - {题号}] 到 Spec 的 10.2 待确认表。
