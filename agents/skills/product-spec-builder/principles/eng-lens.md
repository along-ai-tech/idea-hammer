# 原则：工程视角（Spec 收尾自检）

> 防"改 A 坏 B"。AI 写代码最常见的失误：实现时没考虑"这个字段被历史记录引用过"。

[定位]
    Spec 写完收尾前，主 Agent 显式戴工程师帽子过 5 问。
    这条特别重要——AI 写 Spec 时倾向只关注"未来要实现的功能"，忽略"被历史数据/订单/合规快照依赖的字段"。
    借 gstack `/plan-eng-review` 的"边缘 case + 数据流 + 可测性"思路。

[触发条件]
    - Spec 写完、收尾前必走
    - 涉及业务数据（订单、商品、价格、规则、权限）的产品必走且深走

[5 问]

    [1. 数据快照与历史回溯]
        [覆盖意图]
            防"AI 改商品信息把所有版本的订单都改了"这种上游改完下游挂的事。
        [自检问]
            "这份 Spec 的数据模型里，哪些字段被历史记录引用？这些字段被改后，历史快照还能回溯到原值吗？"
        [不通过信号]
            - 任何"价格/规格/规则/权限/状态"字段无 version / effective_time / deleted_at 软删除设计
            - Spec 里没说"修改是覆盖还是新建版本"
        [补救]
            6. 数据模型节加"快照字段 + 不可变设计"段；或加 SCOPE 进 2.1（"v1 实现不可变快照"）。
            详见 _engineering-constraints/database/versioning-and-immutability.md。

    [2. 数据流与外部依赖闭环]
        [覆盖意图]
            防"Spec 写完漏了某个外部依赖/回调/异步任务，发布才发现跑不通"。
        [自检问]
            "这份 Spec 涉及的所有外部依赖（7. 外部依赖节）都标了'必需'和'失败兜底'吗？任何一个挂掉，系统还能不能完成 P0 用户任务？"
        [不通过信号]
            - 外部依赖表里有"用途"无"失败兜底"
            - 用户核心路径上有未标"必需"的外部 API（支付 / 短信 / 邮件 / 第三方登录）
        [补救]
            7. 外部依赖每行加"失败兜底"列；必需的依赖加到 8. 非功能需求的可靠性类。

    [3. P0 功能可测性]
        [覆盖意图]
            防"P0 写得太虚，dev-builder 不知道测什么"——TDD 铁律要求每个 P0 有可写测试的输入/输出。
        [自检问]
            "每个 P0 REQ 的 AC 7.1 验收标准，能直接写一个 pytest 用例覆盖吗？给和给哪个 mock？"
        [不通过信号]
            - AC 里有"系统应该正确"这种不可测描述
            - AC 没说 mock 谁/谁
        [补救]
            AC 加 Given/When/Then 写死；mock 目标写到 7.2 非功能里的"可测试性"段。

    [4. 边缘 case 与异常路径]
        [覆盖意图]
            防"用户填错/网络断/并发撞车 时系统行为没想"。
        [自检问]
            "每个 P0 FLOW 的边界情况、异常路径（4. 流程节都标了吗？）：用户填错字段、网络断、并发同一资源、第三方超时，分别会怎样？"
        [不通过信号]
            - 4. FLOW 节只有主路径无分支
            - 异常路径只写"重试"没写"重试几次 / 降级 / 报错"
        [补救]
            每个 P0 FLOW 补 边界情况/异常情况/重试策略 段。

    [5. 部署与回滚]
        [覆盖意图]
            防"写完 Spec 才发现没法发布/没法回滚"。
        [自检问]
            "这份 Spec 涉及数据库 migration 吗？migration 失败怎么回滚？首次上线和后续升级路径分别怎么走？"
        [不通过信号]
            - 6. 数据模型改了既有字段类型（破坏性 migration），Spec 没写迁移策略
            - 没标"灰度发布/全量发布/回滚按钮"
        [补救]
            9. 完成定义节加"发布与回滚"清单；migration 加前置/后置脚本。

[输出]
    5 问过完，写一段 ≤ 5 行的 [工程视角自检报告] 到 Spec 末尾。
    漏掉的进 10.2 待确认表；触发的工程约束（Q1 触发的 versioning-and-immutability）
    在 dev-builder 启动必读里强制引用。
