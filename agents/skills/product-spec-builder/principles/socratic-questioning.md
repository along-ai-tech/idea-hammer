# 原则：苏格拉底式提问（PRD 目标层）

> 用户给的需求天然不标准。目标层（为什么 / 为谁 / 价值）不能靠"你觉得呢"收集，要靠追问把模糊表述拆到有证据。
> 核心姿态：不替用户下结论，不满足于第一个答案；用问题让对方自己发现矛盾。

## 一、四步法（每一轮只走一步）

| 步 | 目的 | 问法示例 |
|---|---|---|
| 澄清 | 把形容词换成事实 | "你说的『不方便』，具体是哪一步不方便？" |
| 检验证据 | 让判断有来源 | "这个结论是怎么得出的？最近一次发生是什么时候？" |
| 找反例 | 暴露边界与例外 | "有没有哪种情况下这个判断不成立？" |
| 推到后果 | 逼出优先级与代价 | "如果只能解决其中一半，你留哪一半？为什么？" |

## 二、分主题的追问梯子

### 为什么做（Q1）

1. "最近是什么事让你想到要做这个？"
2. "这件事之前你们是怎么处理的？为什么现在处理不了了？"
3. "如果半年后还是现在这样，会发生什么具体的事？"
4. "这个代价谁来承担？他会不会自己想办法绕过去？"

反例信号：回答里出现"趋势""风口""大家都说"——继续追："具体到你们自己，哪一件事变了？"

### 为谁做（Q1）

1. "最想服务的那个人，上一次遇到这个问题是什么时候？"
2. "他当时手头有什么、缺什么？"
3. "除了他，还有谁会用？他们的问题一样吗？不一样的话先服务谁？"
4. "如果只服务一个人，你选谁？"

反例信号："所有人""开发者都……"——继续追："那就挑一个你认识的、最近抱怨过的人。"

### 核心价值（Q3）

1. "解决之后，他哪一步不用做了？"
2. "哪件事从做不成变成做成？"
3. "这个变化他自己能感知到吗？怎么感知？"
4. "如果只保留一个变化，是哪个？"

反例信号："更高效""体验更好""智能化"——继续追："高效在哪一步？省下多少时间？谁来数？"

## 三、执行规则

- 一次只问一个，下一问必须基于上一答，不按脚本连发
- 用对方的原话复述确认，再进下一层
- 每层追问最多 2 轮；仍答不上来 → 进 §10.1 假设（带依据与猜错后果），不硬逼
- 一次对话最多 3 个阻塞问题，其余记入 §10.2
- 问题要具体到"人、时间、动作"，不接受类别级回答

## 四、反模式

- 连环炮：一次抛 5 个问题，用户只挑好答的答
- 替用户答："我理解你是想要 X 对吧"——把假设当事实
- 引导式提问："你不觉得这样更好吗"——答案已被写进问题
- 问成审讯：只质疑不给方向，用户防备后开始编答案
- 追到用户烦躁还不停：到"便宜能补"的粒度就停

## 五、产出

- Q1–Q3 每问至少留下：一句用户原话 + 一个具体场景/数字
- 追问暴露的矛盾写进 §10.2（如"说给所有人用，但只描述了一个角色"）
- 目标层结论回填 §1.1–§1.4，不另建文档
