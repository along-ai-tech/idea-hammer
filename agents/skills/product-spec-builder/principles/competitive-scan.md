# 原则：竞品扫描 + 行业借鉴

> 没扫过竞品就写 Spec = 闭门造车。只用一种打法扫所有项目 = 失焦。
> 业务参照型：市场已成熟，做法已经定形 → 重点学怎么做得更好；市场机会型：用户痛点未充分满足 → 重点找差异化缝隙。

[定位]

    竞品扫描 = phase-discipline "搜索增强双遍" 第一遍（提问前搜种子）的结构化产出之一。
    行业借鉴 = 同一次搜索的另一个产出。两者并行，不互相替代。

    不是写竞品报告 / 行业综述——是逼用户对"差异化"和"可借鉴"形成可验收的判断。

[项目类型判断 · 路由开关]

    在 Phase 0 业务快筛之后、Phase 1.5 之前判一次，落进 Spec 1.0 产品类型字段。
    后续 Phase 1.5 / 1.6 / 2.1 范围 / 1.6 / 1.7 的填充权重由这个字段驱动。

    类型 | 含义 | 典型场景 | 扫描重心
    ---|---|---|---
    业务参照型 | 公司/团队已有业务方向，问题域成熟，做法已被验证 | 智能客服、电商上架流程、内部审批系统、ERP 改造 | 学方法：1.6 仅作参考（≥2 直接竞品），1.7 重点（≥3 优秀做法必填）
    市场机会型 | 用户痛点未充分满足，市场窗口未定型，差异化是核心 | 宠物节日定制 OPC、新兴 AI Native 工具、垂直 SaaS | 探机会：1.6 严格必填（≥2 直接竞品 + ≥2 替代方案，逼差异化判断），1.7 选填（≥2 顶级品类优秀做法）

    判断三问（任一为是 → 业务参照型）：
        1. 公司是否已有明确业务线，这次是做业务内部的某个工具/流程？
        2. 行业是否已存在公认的成熟方案（"行规"、"标准流程"），目的是适配本公司场景？
        3. 用户主动说"参考 XX 公司做法"、"按行业最佳实践来"、"适配我们公司"？

    否则默认市场机会型。

    写进 Spec 时由用户确认 / 调整。主 Agent 不要单方面猜类型，猜了要问一句"我把它当 X 型，你看对吗"。

## Part 1 · 竞品扫描（差异化）

[纪律]

    1. 直接竞品（≥ 2 个）
        - 同类产品，已经在做同样事
        - 不要求全查清——但要能让用户回答"它的强是什么、弱是什么"
        - 找不到直接竞品本身是信号（市场可能没需求 / 或你是第一）

    2. 替代方案（≥ 2 个）
        - 用户**今天**用什么替代解决（Excel / 微信群 / 纸笔 / 求同事）
        - 这是被忽视的盲区——直接竞品 0 个不代表没竞争，替代方案才是真竞争

    3. "我们凭什么" 必填
        - 每行都要填"我们凭什么不同/更好"
        - 不许写"更好用"——逼成可验证句（"快 10 倍" / "免费" / "本地化" / "针对 X 行业"）

[按类型加权]

    业务参照型：≥ 2 直接竞品（仅作参考），本节弱化差异化要求，重心转向 1.7。
    市场机会型：≥ 2 直接竞品 + ≥ 2 替代方案，必填且每行"我们凭什么"必须可验证。

[Spec 模板 1.6 节填充]

    | 类型 | 名字 | 解决什么 | 怎么收费 | 它的强 | 它的弱 | 我们凭什么 |
    |---|---|---|---|---|---|---|
    | 直接竞品 | A | | | | | |
    | 直接竞品 | B | | | | | |
    | 替代方案 | C（Excel/微信群/...）| | | | | |
    | 替代方案 | D | | | | | |

[不接受的答案]

    - "市面上没有竞品"——第一反应一定是错的，回去重搜
    - "我们更好" / "更优"——不可验证 = 不算差异化
    - 只列竞品不列替代方案——替代方案是真竞争（业务参照型可豁免替代方案，因替代方案就是上一代内部系统本身）
    - "我们做的不一样"——不一样不等于更好

## Part 2 · 行业借鉴（吸收优秀做法）

[纪律]

    1. 借鉴对象（≥ 2 个）
        - 同品类或相邻品类的优秀产品/做法，不必是直接竞品
        - 选的是"某一块做得好"，不是"整体像它"
        - 跨界做法也允许——游戏化来自游戏、协作范式来自飞书/Notion

    2. 借鉴维度必选其一
        - 交互范式（怎么操作 / 信息架构怎么组织）
        - 增长机制（拉新 / 激活 / 留存 / 变现的招数）
        - AI 能力用法（怎么把 AI 嵌进去、怎么避坑）
        - 工程实践（性能 / 稳定性 / 可观测的成熟方案）
        - 商业模式（怎么收费 / 怎么续费 / 怎么扩客单）
        - 任意其他能让 Spec 更聪明、减少发明轮子的维度

    3. "我们怎么用" 必填
        - 每行都要写"我们要 / 不要 / 改造后用"
        - 不许写"可以参考"——必须说出具体落地："把 X 的 Y 用到 Z 场景，但要避开它的 W 问题"

[按类型加权]

    业务参照型：≥ 3 优秀做法（硬性下限），必须落在本公司业务场景里说清楚怎么用——这是这一节的价值核心。
    市场机会型：≥ 2 顶级品类优秀做法（仅顶级品类，避免被细节淹没差异化定位），可不填差异化风险。

[Spec 模板 1.7 节填充]

    | 来源产品/品类 | 借鉴维度 | 它的做法（具体描述） | 我们怎么用 | 借鉴后的差异化风险 |
    |---|---|---|---|---|
    | {{某产品 / 某品类做法}} | {{交互 / 增长 / AI / 工程 / 商业模式 / ...}} | {{具体怎么做，不是"很好"} | {{要 / 不要 / 改造后用，落到我们哪块}} | {{照搬会丢什么差异，怎么补}} |
    | {{}} | {{}} | {{}} | {{}} | {{}} |

[不接受的答案]

    - "参考 Notion"——Notion 那么大，借鉴它什么？哪一点？落到我们哪？
    - "做得很好"——不可观察 = 不可借鉴
    - 只列借鉴对象不写"我们怎么用"——抄答案不是借鉴，是堆砌
    - 把直接竞品改头换面塞进 1.7——那是 1.6 的活
    - 业务参照型只写"参考 X 公司的做法"不写落地——回退成竞品扫描 1.6，不是借鉴

---

[写入位置]

    Spec 模板：1.0 顶部填项目类型，1.5 成功标准之后填 1.6 竞品扫描，再填 1.7 行业借鉴，再进 2. 范围。
    两节都按项目类型的权重填了 Spec 才能发布。

[搜索增强]

    0-1 进场时先用 WebSearch 搜：
        - 业务参照型搜：主关键词 + "best practices" / "行业标准" / 同行案例 / 跨界关键词 → 行业借鉴素材为主
        - 市场机会型搜：主关键词 + "alternatives to X" / "X vs Y" / 行业报告 → 竞品扫描素材为主
    搜出来的前 5 个候选做粗筛：
        - 最相关的进 Spec 1.6（直接竞品 / 替代方案）
        - "某一块做得好"的进 Spec 1.7（行业借鉴）
    同一产品可能两边都进——它在 1.6 是竞品，在 1.7 是某具体做法的来源，按角色分别填。

[触发条件]

    - 0-1 模式必走项目类型判断 + 竞品扫描 + 行业借鉴
    - 迭代模式（小功能）默认跳过，仅当用户主动说"我要挑战 XX / 看看行业怎么做"时触发
    - 主 Agent 可根据改动的范围与方向自行判断是否需要做行业借鉴
