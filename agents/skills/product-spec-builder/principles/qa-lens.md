# 原则：QA/测试视角（Spec 收尾自检）

> 防"Spec 写完开发说不知道怎么测"。借 gstack `/plan-led-test` 的"测什么 + 怎么测 + 谁来测"思路。

[定位]
    Spec 写完收尾前，主 Agent 显式戴 QA 帽子过 4 问。
    这条对 dev-builder 的 TDD 纪律负责——没清晰的 AC 和测点，TDD 写不下去。

[触发条件]
    - Spec 写完、收尾前必走
    - 迭代模式（小功能）跳过，除非涉及新接口/新数据字段

[4 问]

    [1. 每个 P0 能否被 1 条端到端用例覆盖]
        [覆盖意图]
            防"Spec 里 P0 列了一堆，但端到端串不起来"。
        [自检问]
            "对每个 P0 SCOPE，能不能从用户打开产品走到任务完成，1 条 happy path 用例覆盖？给我列 SCOPE → AC 的映射。"
        [不通过信号]
            - P0 SCOPE 没对应的 TASK 或 FLOW
            - P0 SCOPE 列了但 AC 7.1 找不到对应条目
        [补救]
            9. 完成定义节加"P0 覆盖矩阵"表（SCOPE / TASK / FLOW / AC / 用例 ID 五列）。

    [2. 边界 case 是否每态都有显式处理]
        [覆盖意图]
            防"Spec 写完但每个功能只有主路径没有边界"。
        [自检问]
            "每个 REQ 的 5 态（默认/加载/空/错误/成功）都显式定义了吗？空态和错误态能区分吗？"
        [不通过信号]
            - REQ 没写 5 态
            - 空态和错误态长得一样（用户分不清）
        [补救]
            REQ 模板 5 态补全；空态必须有引导文案、错误态必须有重试按钮。

    [3. 非功能需求是否都给数字]
        [覆盖意图]
            防"Spec 写完但 8. 非功能全是'要快、要安全'这种不可验收词"。
        [自检问]
            "8. 非功能需求里'响应要快'换成毫秒数是多少？'安全'具体指什么？6 类（性能/安全/隐私/兼容/可靠/可访问）每类都有数字或明确'不要求'吗？"
        [不通过信号]
            - 8. 表里有"快/安全/完善"等模糊形容词
            - 6 类有 ≥ 1 类完全空白
        [补救]
            8. 表每行必须给数字或"明确不要求"；隐私默认值见 principles/ai-capability-awareness.md。

    [4. AI 功能的概率性是否钉死]
        [覆盖意图]
            防"AI 功能上线后发现质量不稳/失败兜底缺失"——AI 是概率性的，不钉死就是赌。
        [自检问]
            "每个 AI 功能：质量条（命中率多少敢上）、触发方式（建议还是自动）、不确定时怎么办、绝不能做什么、降级策略——5 项都填了吗？"
        [不通过信号]
            - AI 功能列了但"AI 能力规格"表 5 列有 ≥ 1 列空白
            - AI 护栏（绝不能做）没写
        [补救]
            AI 能力规格表 5 列补全；护栏单列写明。

[输出]
    4 问过完，写一段 ≤ 5 行的 [QA 视角自检报告] 到 Spec 末尾。
    漏掉的进 10.2 待确认表；触发 TDD 纪律的（Q1 触发的端到端用例矩阵）
    由 dev-builder 在 Phase 启动时强制验证。
