# 原则：Phase 规划纪律

> Phase 拆得对，dev-builder 才能照着干。每个 Phase 独立可验收。

## 可验证

- 每个 Phase 完成后必须能编译、能运行、能跑起来看到效果
- 不允许"写一堆跑不起来"的 Phase

## 依赖正序

- 地基先打：基础设施排在业务功能前
- 被依赖方先做
- 关键路径优先

## 粒度适中

- 一个 Phase = 一个可独立验收的功能单元
- 通常 1-3 个核心交付物
- 交付清单 > 5 项或涉及 3 个不相关功能 → 太大
- 只有 1 项简单交付 → 太小

## 文件路径明确

- 每个 Phase 列出要创建或修改的具体文件路径
- 不写"实现聊天功能"这种泛描述
- 路径不含通配符 / 占位符

## 无占位符

- 不允许 TBD / 待补充 / "类似 Task N"
- 每个 Task 描述完整到没有项目上下文的人也能照着开工

## 依赖图

- 列功能点（从 Spec 提取）
- 问每个"依赖什么"
- 构建 DAG（依赖图）
- 拓扑排序得 Phase 顺序
- 基础设施是根节点

## 联网优先

- 技术选型、关键依赖先 WebSearch 确认版本、兼容性、breaking changes
- 不靠过期记忆
