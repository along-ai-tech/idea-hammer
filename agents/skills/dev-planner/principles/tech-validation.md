# 原则：技术选型验证

> 技术栈选错返工代价大。WebSearch 验证 + 用户拍板是必经路径。

## WebSearch 必查

- 框架版本（最新稳定版）
- 重大 breaking changes
- 安全漏洞（CVE）
- 兼容性问题（语言运行时 / 操作系统）

## 用户决策

- 有 2-3 个合理选项时给用户选（不要替用户做架构决策）
- 询问时附简明对比（优缺点 / 适用场景 / 学习成本）
- 用户不拍板 → 不进入 Phase 拆分

## 风险前置

- 没用过的框架 → 排早（避免后期发现问题）
- 关键第三方 API → 排早（先做 spike）
- 性能敏感点 → 排早（先做 benchmark）

## 不选型不生成

- 技术栈没确定 → 不生成 DEV-PLAN.md
- 半成品 Phase 不写出去
- "先这样后面改" 是反模式
