# 流程：生成模式（从 0 生成 DEV-PLAN.md）

> 用户已有 Product-Spec.md，需要从 0 生成 DEV-PLAN.md。

## 阶段 1：加载输入

**目标**：确认输入齐全
**动作**：
1. 读 Product-Spec.md 全文
3. 读 Design-Brief.md（可选）
4. 读设计稿（如有）
5. 读现有项目代码（如有）

**完成**：输入加载 + 现状理解

## 阶段 2：技术栈验证

**目标**：技术栈确定并验证
**动作**：
1. 读 Spec 提到的技术栈
2. WebSearch 验证（版本 / 兼容性 / CVE / breaking changes）
3. 有 2-3 个合理选项 → 问用户选
4. 补全：包管理器 / 部署目标 / 工具链

**完成**：技术栈确定

## 阶段 3：依赖图 + Phase 拆分

**目标**：拆出有序 Phase
**动作**：
1. 列功能点（从 Spec 提取）
2. 问每个"依赖什么"
3. 构建 DAG（依赖图）
4. 拓扑排序得 Phase 顺序（基础设施是根节点）
5. 优先级：核心先、重要中间、辅助和收尾最后
6. 风险前置

**完成**：Phase 序列

## 阶段 4：交付清单 + 关键文件

**目标**：每个 Phase 写清楚做什么
**动作**：
1. 每个 Phase 列交付清单（动词开头，描述用户可感知功能）
2. 每个 Phase 列关键文件（具体路径）

**完成**：DEV-PLAN.md 草稿

## 阶段 5：信息充足度检查（详见 sufficiency-check.md）

**完成**：质量门禁达标

## 阶段 6：生成 + 自检

**目标**：输出 DEV-PLAN.md
**动作**：
1. 按 templates/dev-plan-template.md 填
2. 自检：无 TBD / Spec 功能全覆盖 / 依赖不冲突
3. 写文件到项目根目录

**完成**：DEV-PLAN.md 落地

## 失败处理

- 阶段 2 技术栈多选 → 问用户
- 阶段 3 Phase 太大/太小 → 重新拆
- 阶段 5 任何项不达标 → 不生成，回去补
