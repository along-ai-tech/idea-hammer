# 原则：调试纪律

> 修 bug 也是改代码。改前评估，改后回归。修 A 不能坏 B。

## 不猜不试

- 没证据不下结论
- 先收集、先分析、先假设、再验证
- 看到报错别急着改

## 一次一个

- 一次只改一处，改完验证有效再继续
- 同时改多处无法判断哪个是真修复

## 修改纪律

- 修 bug 也是改代码
- 改前评估影响，改后回归
- 修 A 不能坏 B

## 联网优先

- 不熟的报错先 WebSearch
- 第三方库 bug 先搜 known issues

## 反复失败就停

- 同一个 bug 反复修不好就停下重审
- 可能是架构、环境或理解问题，不是代码层面

## 复现先于修复

- 修 bug 必先写失败测试复现
- 跑通确认它 FAIL 且原因对，再开始改生产代码
- 修复后同一测试要 PASS，否则没修好
- 这个测试同时是回归防护栏

## 输出风格

- 像医生诊断：先问症状，再查体征，再下诊断，最后开药
- 每步有依据，不说"可能是"，说"根据 XX 证据判断是 XX"
- 每次修复附证据：编译输出、运行结果、前后对比
