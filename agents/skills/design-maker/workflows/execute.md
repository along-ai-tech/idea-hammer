# 流程：生成设计交付物

> 先过 UX 门禁，再出稿；交付按 Handoff 七件，验收按四类 QA。只给截图不算完成。

## 阶段 0：UX 门禁

**动作**：
1. 读 Design-Brief，逐项检查 Persona、User Flow（六项）、IA、Wireframe（五项）
2. 检查 P0 流程是否走通（入口 → 每步信息 → 分支 → 失败处理 → 二次确认 → 完成态）
3. 缺项或只有正常路径 → 退回 design-brief-builder 补齐，不出高保真

**完成**：UX 四要素齐全，P0 流程无断点

## 阶段 1：加载输入

**动作**：
1. 读 Product-Spec.md 提取 UI 功能、页面涉及的数据与操作
2. 读 Design-Brief.md 提取页面 / 组件 / Token / 交互规则
3. 读技术栈与既有设计系统（组件库版本、Token 来源），确定复用边界
4. 确认设计工具（MCP）：Pencil / Figma；未连接则按无设计稿模式降级，并在交付物标注

**完成**：输入就绪，复用边界明确

## 阶段 2：提取清单

**动作**：
1. 页面清单：Spec UI 功能 + Brief 页面清单 + User Flow 三处交叉，标 SCREEN 编号与 P0 / P1
2. 状态清单：每页按八态（正常 / Loading / Empty / Error / Disabled / 无权限 / Submitting / Success）逐格表态，不适用标 N/A 并写原因
3. 组件清单：先映射既有组件（CMP 编号、变体、状态、使用页面），确需新组件另列
4. Token 清单：color / space / radius / shadow / font / motion，附前端映射方式

**完成**：页面 / 状态 / 组件 / Token 四份清单

## 阶段 3：用户对齐

**动作**：
- 展示四份清单与总数（页面数、状态格数、组件数）
- 标注降级项（无设计稿、复用组件、待补 Token）
- 用户确认后开始

**完成**：用户同意

## 阶段 4：执行

**动作**：
1. 取设计工具 guidelines
2. 设变量（颜色 / 字体 / 间距 / 圆角 / 动效）
3. 建组件：按清单逐个实现变体与状态，每个组件截图验证
4. 先搭页面骨架（布局 + 路由 + 空壳组件），再填充：
   - 只用清单内组件拼装，不临时新造
   - 填真实内容（不用 Lorem ipsum）
   - 对照 Spec、Brief 与线框
   - 截图验证
5. 覆盖八态变体，交互态（确认 / 处理中 / 成功 / 失败 / 超时 / 重试）逐条落实

**完成**：所有页面 + 八态 + 组件变体齐全

## 阶段 5：Handoff 七件

**动作**：
1. 设计稿（页面 + 关键状态）
2. Design Tokens（变量表 + 前端映射）
3. Component Inventory（变体 / 状态 / 使用页面）
4. Interaction Spec（每个操作的确认 / 处理中 / 成功 / 失败 / 超时 / 重试）
5. Page State（每页八态矩阵）
6. Asset Manifest（图标 / 图片 / 字体：名称、尺寸、格式、来源、是否装饰性）
7. Responsive Rules（断点、栅格、折叠顺序、最小可操作尺寸）

缺任一项即视为交付不完整，不进入下一阶段。

**完成**：七件齐全，回写到 Design-Brief 对应小节

## 阶段 6：视觉验收

**动作**：
按四类逐项自检，未通过项修复后复验：

| 类别 | 检查内容 |
|---|---|
| Visual QA | 布局、间距、字号、颜色、圆角、图标、对齐、状态样式 |
| Interaction QA | 点击反馈、loading、防重复提交、确认与取消、错误恢复 |
| Responsive QA | 断点布局、栅格折叠、表格横向滚动、触控尺寸 |
| Accessibility QA | 键盘可达、焦点可见、label 关联、对比度、语义、替代文本 |

**完成**：四类均有结论，修复项已复验

## 阶段 7：交付

**动作**：
1. 完整性校验：对照 Spec 与 Brief 检查页面、组件、状态无遗漏
2. 用 contracts/output.schema.json 校验交付物结构
3. 输出交付报告（含验收结论与降级说明），引导 /dev-planner 排前端任务

**完成**：报告落地，设计输入可供 DEV-PLAN 与前端实现引用
