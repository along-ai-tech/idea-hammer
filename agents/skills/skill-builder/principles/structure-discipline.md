# 原则：结构纪律（三层模块化）

> Skill 不是大文件，是 Section 的组合。改一个 Section 不影响其他。

## 三层模块化

- **Section** 是原子能力。维度清单定义查什么收什么，策略定义怎么做，工作流程定义什么顺序。改一个 Section 不影响其他。
- **Skill** 是多个 Section 的组合，解决一个领域问题。
- **AGENTS.md** 编排 Skill 的顺序和触发，改工作流不改 Skill 内容。

## Section 分类

| 优先级 | 名称 | 含义 |
|---|---|---|
| 必须有 | [任务] | 一两句话讲清做什么、产生什么产出物 |
| 必须有 | [依赖检测] | 启动第一步，缺什么提示用户补 |
| 必须有 | [文件结构] | 目录布局（让读者一眼看到） |
| 必须有 | [第一性原则] | 跨 Section 共享的价值取向 |
| 必须有 | [初始化] | 启动动作 |
| 推荐有 | [输出风格] | 汇报风格约束 |
| 推荐有 | [XX维度清单] | 涉及查什么收什么的场景 |
| 推荐有 | [XX策略] | 涉及怎么做的场景 |
| 按需有 | [信息充足度判断] | 生成前的质量门禁 |
| 按需有 | [回退策略] | 失败处理 |
| 按需有 | [Phase 完成度判断] | 多阶段流程的完成标准 |
| 按需有 | 多模式工作流程 | 0-1 / 迭代 / 故障处理等多模式 |

## 交互模式定参照

| 模式 | 参照 Skill |
|---|---|
| 对话采集型 | product-spec-builder / design-brief-builder |
| 自主分析型 | dev-planner / code-review |
| 执行操作型 | dev-builder / release-builder |
| 诊断修复型 | bug-fixer |

## 模板优先

- 先读 templates/skill-template.md 骨架按结构填
- 不从零写

## 参照现有

- 创建前读 1-2 个交互模式最接近的已有 Skill 保持一致
- 不发明新格式

## 最小必要

- 只建需要的 Section
- 不为"看起来完整"加空内容

## 联网优先

- 涉及不熟的领域先 WebSearch 了解最佳实践
- 再设计维度和策略
