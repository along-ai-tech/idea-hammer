# 原则：先 UX，后 UI（设计分层门禁）

> 设计不是从配色开始。先回答"用户怎么完成任务"，再回答"页面怎么呈现"，最后才是"视觉长什么样"。

## 一、三层与顺序

| 层 | 回答什么 | 产物 | 未完成的后果 |
|---|---|---|---|
| UX | 用户如何完成任务 | Persona、User Flow、IA、Wireframe | 页面结构拍脑袋，做完发现流程走不通 |
| UI | 页面如何呈现 | 布局、层级、组件、Token | 视觉漂亮但信息主次错乱 |
| Interaction | 操作后系统如何响应 | 确认、处理中、成功、失败、超时、重试 | 用户点了没反馈，重复提交、误操作 |

硬门禁：**UX 四要素未齐，不得进入高保真 / 视觉设计**；P0 流程未走通，不得生成页面稿。

## 二、UX 四要素

### 1. Persona（角色 / 任务 / 关注点）

- 角色来自 Spec §1.2，不临时发明
- 写清：他要用这个页面完成什么任务、最关注哪 1–2 个信息、最怕什么
- 一类角色一行，不写"所有用户"

### 2. User Flow（流程）

每条 P0 流程必须写全六项：

| 项 | 要求 |
|---|---|
| 入口 | 从哪进（导航 / 链接 / 通知 / 空态引导） |
| 每步所需信息 | 这一步要看到什么、填什么 |
| 分支 | 有哪些分叉，按什么条件走 |
| 失败处理 | 网络失败 / 校验失败 / 权限不足 / 冲突，各去哪 |
| 二次确认 | 哪些操作必须确认（删除、禁用、批量、资金） |
| 完成态 | 用户怎么知道成功，下一步去哪 |

### 3. Information Architecture（IA）

- 菜单结构：一级 / 二级菜单，谁在哪个层级
- 页面层级：页面所属模块、父子关系
- 模块归属：同一功能不跨三处入口
- 导航规则：当前位置可感知、返回路径明确

### 4. Wireframe（线框）

- 布局：区域划分、主次关系
- 内容区域：每块放什么信息
- 信息层级：什么最先看到
- 操作入口：主操作 / 次操作 / 危险操作的位置
- 页面关系：从哪来、到哪去
- 线框可以是文字版 / ASCII / 低保真，但必须能讲清上述五项

## 三、Interaction 层最小要求

- 每个异步操作定义：进行中（按钮 loading / 禁用重复提交）、成功（反馈 + 去向）、失败（错误信息 + 可否重试）、超时（提示 + 重试入口）
- 危险操作：二次确认 + 说明后果 + 提供取消
- 禁用态必须说明原因（无权限 / 前置条件未满足 / 已下线），不能只灰掉
- 键盘焦点顺序与可见焦点态在 Brief 中声明

## 四、不合格信号

- 先出高保真页面，再补流程说明
- User Flow 只有正常路径，没有失败与二次确认
- 页面清单有页面，但说不清从哪进、完成后去哪
- 组件状态只有 default / hover，没有 loading / disabled / error / focus
- 用"参照 XX 产品"代替 IA 与流程设计

## 五、产出与衔接

- 产物写进 Design-Brief：Persona（§2.0）、User Flow（§2.4）、IA（§2.1）、Wireframe（§2.5）
- 通过后方可进入组件与视觉（§4 / §5），再交 design-maker 出稿
