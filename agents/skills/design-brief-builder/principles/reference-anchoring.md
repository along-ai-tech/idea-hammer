# 原则：参考锚定

> 用真实产品当锚点，"像 Linear 还是像 Notion" 比 "简洁还是丰富" 有效十倍。

## 为什么

- 用户不是设计师，问"你要什么风格"等于没问
- 真实产品 = 共同语境，比形容词更具体

## 怎么做

### 二选一引导

展示两个对立方向让选，每对带真实产品参考：

| 维度 | 选项 A | 选项 B |
|---|---|---|
| 信息密度 | Linear 紧凑 | Notion 宽松 |
| 色彩温度 | Stripe 冷 | Airbnb 暖 |
| 正式程度 | Bloomberg 严肃 | Figma 活泼 |
| 主题 | GitHub 默认深 | Google Docs 默认浅 |
| 字体调性 | Inter 几何无衬线 | IBM Plex 衬线 |

### 终端型和对话式 Agent

**别用界面产品当锚**（错形态），用同形态的：
- 命令行编程 Agent
- 终端工具
- AI 编辑器（Cursor / Windsurf / Continue）

进场前先搜当前公认做得好的当锚（这类产品迭代快）。

### 品牌人格化

用生活类比绕开术语：

> "产品是个走进房间的人，穿西装还是卫衣，张扬还是内敛"

### 反面排除

> "有没有哪种风格你一看就讨厌？知道你不要什么跟知道你要什么一样有用"

### 矛盾检测

偏好冲突时逼排序，**不允许"都要"**。

## 反模式

- ❌ "你想要什么风格"（开放题）
- ❌ 用错形态的参考（界面产品锚 Agent）
- ❌ "看起来都差不多你随便选"（没立场）
- ❌ 偏好冲突时"都要吧"（回避决策）
## 选择题 vs 开放题

- 永远给 2 到 3 个具体选项（选择题）
- 不给开放题（"你想要什么风格"等于没问）
