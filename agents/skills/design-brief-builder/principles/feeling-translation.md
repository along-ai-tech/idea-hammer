# 原则：感受翻译表

> 用户说抽象词，逼成具体属性。绝不直接接受形容词。每翻译完 recap 回去确认。

## 翻译表

| 形容词 | 翻译成的属性决策 |
|---|---|
| 简洁 clean | 大留白 + 克制配色 + 少字重 |
| 高级 premium | 高对比 + 大量负空间 + 克制强调色 + 精致衬线或精准无衬线 + 更慢更松的间距 |
| 现代 modern | 扁平表面 + 无衬线 + 明亮饱和强调色 + 简化图标 |
| 紧凑专业工具 | compact 密度，4px 步进缩间距，但 alert / 表单 / 小点击区不缩 |
| 活泼 playful | 大圆角 pill + 暖色亮色 + 表现性动效 |
| 技术感 工程感 | 等宽或近等宽字体 + 克制色板 + 高信息密度 + 功能性动效不装饰 + 方角精确边框 |
| 透明可信 Agent 向 | 显式展示在做什么 + 动作前先示意再执行 + 全程可中断 + 不黑箱不替用户做主 |

## 用法

用户说"我想做高级感"：

```
1. 查表："高级 premium" → 高对比 + 大量负空间 + ...
2. Recap："你说高级感，我理解是要高对比 + 大量留白 + 克制强调色，像爱马仕或苹果那种。OK 吗？"
3. 用户确认 → 写入 Design-Brief.md
4. 用户纠正 → 重新翻译
```

## 关键纪律

- **绝不直接接受形容词**："简洁" 不是设计方向，要翻译成属性
- **每翻译必 recap**：让用户确认理解对
- **不带入自己的审美**：以用户翻译结果为准
- **用户矛盾时逼排序**："你说现代又高级，这两个有矛盾"

## 反模式

- ❌ "简洁 = Notion 那种"（太早具体化）
- ❌ 不 recap 直接写
- ❌ 用户说"现代"就照搬现代模板（没问具体哪一面）
- ❌ 引入自己的偏好（"我个人觉得高端应该是..."）
