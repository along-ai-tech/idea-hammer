本模板用于生成设计规范文档。设计工具读取此文档来确定视觉方向，dev-builder 读取此文档来确定代码中的样式实现。

# 设计规范：{{产品名称}}

## 0. AI 使用说明

- 本文档定义产品的界面结构、视觉系统、组件、状态和交互规则。
- Product Spec 是功能范围的事实来源；本文档不得新增 Product Spec 没有定义的核心功能。
- 本文档按产品形态分轨。界面型填 §2 信息架构、§3 页面规格、§5 视觉系统、§8.3 设备响应式；终端型与对话式 Agent 形态改填 §A，§5 走 A.5 终端口径，无关的界面型段标 N/A。叠加形态两轨都填，各占其位。
- AI MUST 优先设计 P0 flows 和 P0 screens。
- AI MUST 先完成 UX 四要素（Persona / User Flow / IA / Wireframe），UX 未定不得进入高保真或视觉细化。
- AI MUST 覆盖正常、加载、空、错误、禁用、无权限、提交中、成功八种页面状态。
- AI MUST 写清每个异步交互的确认、处理中、成功、失败、超时与重试。
- AI MUST 保持页面、组件、交互和视觉 tokens 的一致性。
- AI MUST 按 §9 的 Handoff 七件交付，只给截图不算完成。

## 写作要点

1. **UX 先行**：目标用户 + Persona + 导航 + 页面清单 + 页面关系 + User Flow 六项 + Wireframe 五项先写全；UX 未定不写视觉细节。
2. **设计方向**：设计目标一句；产品气质 4 维（语气 / 密度 / 视觉风格 / 情绪）；设计原则可操作；参考产品拆 load-bearing 属性（「像 Stripe」是症状不是规格），反参考当边界 fence。
3. **信息架构**：导航结构 + 页面清单（每页关联 FLOW / REQ、标 P0 / P1）+ 页面关系。
4. **页面规格**：每个有设计决策空间的页面写布局 / 内容层级 / 用的组件 / 八态 / 响应式；纯后端页跳过。
5. **组件规格**：先列组件清单（§4.0），再写核心组件的变体 + 状态 + 内容规则 + 可访问性；组件编号 CMP 供页面引用。
6. **视觉系统**：色彩 / 字体 / 间距 / 形状用 token 表，附前端映射；具体值定不下来标 [待补充] 交设计工具，但方向要明确。
7. **交互与反馈**：全局交互规则 + 五场景反馈 + 动效克制还是明显；异步操作写全确认 / 处理中 / 成功 / 失败 / 超时 / 重试。
8. **UX 文案**：语气 + 按钮 / 表单 / 空态文案规则。
9. **可访问性与响应式**：a11y 逐条勾、对比度和动效偏好表态、响应式断点逐档、八态矩阵逐格填。
10. **交付与验收**：Handoff 七件齐全，视觉验收四类有结论。
11. **实现说明**：技术栈偏好、暗色、品牌资产、必用 / 避免的设计模式。
12. **假设与待确认**：定不下来的写假设或待确认，不凭空补。
13. **跨文档一致**：SCREEN / CMP 编号呼应 Product Spec 的 FLOW / REQ，两边 P0 一致。
14. **形态分轨**：先认形态填 §1.0。界面型走 §2 §3 §5 §8.3；终端型和对话式 Agent 走 §A，§5 改 A.5 终端口径，无关段标 N/A。Agent 形态的授权与透明度 A.4 必填，别留空。
